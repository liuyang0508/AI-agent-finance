## 1. 项目背景

### 业务问题

金融投研领域，分析师面临以下核心痛点：

| 痛点 | 描述 |
|------|------|
| 数据分散 | 财报 PDF、实时行情、新闻资讯分散在不同来源 |
| 人工耗时 | 从问题提出到出具研报需数小时人工操作 |
| 数学幻觉 | 直接让 LLM 计算 PE/ROE 等指标会产生错误结果 |
| 质量难评估 | 生成内容的准确性、召回完整性难以量化 |

### 解决方案

构建 Multi-Agent 自动化投研系统，自动完成：

```
用户提问 → 意图识别 → 多源数据检索 + 实时数据获取 → 多角色专家协作分析 → 自动生成研报
```

## 2. 技术栈清单

### 框架层

| 组件 | 库/版本 | 用途 |
|------|---------|------|
| Agent 编排 | `langgraph >= 0.2.0` | 多 Agent 状态机、条件路由、Checkpointer |
| LLM 调用 | `langchain-openai >= 0.2.0` | 统一封装 GLM API 调用（OpenAI 兼容格式）|
| 工具框架 | `langchain >= 0.3.0` | `@tool` 装饰器、`create_react_agent` |

### 模型层

| 模型 | 用途 |
|------|------|
| `glm-4-plus` | 意图识别、HyDE 文档生成、财务分析、风控分析、研报生成 |
| `embedding-2`（智谱） | 文本向量化，通过 OpenAI 兼容接口调用 |
| `BAAI/bge-reranker-v2-m3` | Cross-Encoder 重排序，本地运行，支持中英双语 |

### 数据层

| 组件 | 库/版本 | 用途 |
|------|---------|------|
| 向量数据库 | `chromadb >= 0.5.0` | 本地持久化向量存储，支持增量入库 |

| 服务 | 用途 | 重试策略 |

| Alpha Vantage `GLOBAL_QUOTE` | 实时股价行情 | tenacity 重试 3 次，指数退避 |

### 工程层

| 组件 | 库 | 用途 |

## 4. 核心模块详解

### 4.1 Supervisor Agent（`src/agents/supervisor.py`）

**角色：** 系统总调度，不执行分析，只做两件事。

**意图识别实现：**

```
Few-shot Prompt（4个示例）
        ↓
 调用 GLM（temperature=0）
        ↓
 返回意图标签（4类）
        ↓
 字符串校验 → 提取 → 兜底默认"财报解读"
```

**4 类意图：**

| 标签 | 含义 | 首个分配节点 |
|------|------|-------------|
| `industry_overview` | 行业综述 | retrieval_agent |
| `stock_comparison` | 个股对比 | retrieval_agent |
| `financial_report` | 财报解读 | retrieval_agent |
| `realtime_query` | 实时行情/新闻 | realtime_agent |

**任务分配逻辑（`_review_and_dispatch`）：**

- 实时行情意图：`realtime → report → END`（跳过 RAG 和分析）
- 其他意图：`retrieval → financial → risk → realtime → report → END`
- 防死循环：`MAX_ITERATIONS = 10`，超出强制进入报告生成

---

### 4.2 RAG 检索模块（`src/rag/`）

**完整 Pipeline（`RAGPipeline.query()`）：**

```
用户问题
   ↓
HyDERetriever.retrieve()
   ├── 调用 GLM 生成 150-200字 假设性分析文档（temperature=0.3）
   ├── 失败则降级：直接用原始问题
   └── 用假设文档向 ChromaDB 执行 similarity_search（top_k=10）
   ↓
CrossEncoderReranker.rerank()
   ├── 构建 (query, doc) 对
   ├── BAAI/bge-reranker-v2-m3 批量打分
   └── 降序排序，返回 top_k=5
   ↓
返回含 content / source / score 的文档列表
```

**文档入库 Pipeline（`DocumentEmbedder.embed()`）：**

```
data/pdfs/*.pdf
   ↓ Marker（保留表格 Markdown 结构）
   ↓ 自定义跨页表格合并（正则检测相邻同表头表格）
   ↓ 噪声清理（去页码、去重复页眉页脚）
data/markdown/*.md
   ↓ RecursiveCharacterTextSplitter
     chunk_size=1000, overlap=200
     分隔符优先级：\n\n > \n > 。 > ；
   ↓ GLM Embedding-2 向量化
   ↓ ChromaDB 持久化（增量，跳过已入库文件）
data/vectorstore/
```

---

### 4.3 检索 Agent（`src/agents/retrieval_agent.py`）

**简化 ReAct 实现：**

```
第一轮：pipeline.query(原始问题, use_hyde=True)
          ↓
       上下文长度 < 200 字符？
          ↓ 是
       LLM 改写问题（提取核心财务指标 + 公司名）
          ↓
       第二轮：pipeline.query(改写后问题, use_hyde=True)
          ↓
       格式化为 Markdown → state.rag_context
```

> 注意：这是简化版 ReAct（固定最多 2 轮），不是标准的循环推理。

---

### 4.4 实时数据 Agent（`src/agents/realtime_agent.py`）

**唯一真正使用 ReAct 的 Agent：**

```python
create_react_agent(model=self._llm, tools=_REALTIME_TOOLS)
```

工具自动调用流程（由 LangGraph 内置处理）：

```
用户问题
   ↓
LLM 决策：调用哪个工具 + 参数
   ↓
工具执行（get_stock_quote / get_financial_news / calculate_financial_metric）
   ↓
Observation 返回 JSON
   ↓
LLM 根据结果决策：是否继续调用 or 生成最终回答
   ↓
最终 AIMessage → state.realtime_data
```

**3 个工具：**

| 工具 | 数据源 | 输出 |
|------|--------|------|
| `get_stock_quote` | Alpha Vantage `GLOBAL_QUOTE` | 价格/涨跌额/涨跌幅/成交量 |
| `get_financial_news` | Alpha Vantage `NEWS_SENTIMENT` | 标题/摘要/来源/情感标签 |
| `calculate_financial_metric` | 本地 Python 计算 | 8 种财务指标精确值 |

---

### 4.5 财务分析 Agent（`src/agents/financial_agent.py`）

- 角色：CFA 资质财务分析师（SystemPrompt 定义）
- 输入：`state.rag_context`（历史财报片段）
- 分析框架：盈利能力 → 成长性 → 现金流 → 估值水平
- 输出：带综合评级的财务分析（强烈推荐/推荐/中性/回避）

---

### 4.6 风控 Agent（`src/agents/risk_agent.py`）

- 角色：独立风控专家，**专门挑战**财务分析结论（防止回声室效应）
- 输入：`state.rag_context` + `state.financial_analysis`
- 风险维度：财务/行业竞争/政策监管/估值
- 输出：每个风险点含触发条件 + 影响程度（高/中/低）+ 综合风险等级

---

### 4.7 报告生成器（`src/report/generator.py`）

汇总所有子 Agent 输出，调用 GLM（temperature=0.4）生成标准 5 章节研报：

```
执行摘要 → 公司/行业概况 → 财务分析 → 风险评估 → 投资结论
```

注意：`rag_context` 截断为前 2000 字符传入，避免超出上下文窗口。

输出保存为 `reports/{timestamp}_{query前20字}.md`，含 YAML Front Matter 元数据。

---

### 4.8 评测模块（`src/evaluation/evaluator.py`）

```
EvalRequest（问题 + 答案 + 上下文列表 + 可选参考答案）
   ↓
HuggingFace Dataset 格式转换
   ↓
Ragas evaluate()（调用 GLM 作为裁判 LLM）
   ├── Faithfulness     — 结论是否忠实于上下文（无幻觉）
   ├── Answer Relevancy — 是否切实回答了问题
   ├── Context Precision — 检索文档是否真正有用
   └── Context Recall   — 相关信息是否被充分检索（需要 ground_truth）
   ↓
保存为 reports/eval_{timestamp}.json
```

```
LangGraph       ──→ main.py          final_state
```

## 6. 数据流链路图

### 6.1 离线入库链路（一次性 / 增量更新）

```
  data/pdfs/
  ┌─────────┐
  │财报 PDF  │
  └────┬────┘
       │
       ▼
  ┌─────────────────────────────────────┐
  │  Marker (marker-pdf)                │
  │  PDF → Markdown                     │
  │  · 保留表格为 | col | col | 格式     │
  │  · 识别图表、页眉页脚                 │
  └────┬────────────────────────────────┘
       │
       ▼
```

## 9. AgentState 数据结构

```python
class AgentState(TypedDict):
    # 对话历史（add_messages 追加语义，不覆盖）
    messages: Annotated[list[BaseMessage], add_messages]

    # 输入
    user_query: str          # 用户原始问题

    # Supervisor 控制字段
    intent: Optional[str]    # 意图标签（4类）
    next_agent: Optional[str]# 下一个节点名称
    iteration: int           # 当前迭代次数（上限 10）

    # 各 Sub-Agent 输出（按流水线顺序填充）
    rag_context: Optional[str]          # 检索文档（Markdown）
    financial_analysis: Optional[str]   # 财务分析结论
    risk_assessment: Optional[str]      # 风险评估结论
    realtime_data: Optional[str]        # 实时行情/新闻摘要

    # 最终输出
    final_report: Optional[str]         # Markdown 研报全文
```

**Checkpointer 机制：**

- 使用 `MemorySaver`（内存级），每次调用 `graph.invoke()` 时传入 `thread_id`
- 支持同一 `thread_id` 的断点续传（进程内有效，重启后丢失）
- 生产环境可替换为 `SqliteSaver` / `PostgresSaver`

## 10. 关键设计决策与实现细节

### 10.1 意图识别：为什么放弃 Semantic Router？

| 方案 | 优势 | 劣势 |
|------|------|------|
| Semantic Router（原计划）| 极速，无需 LLM 调用 | 需要为每类意图维护示例向量，依赖版本不稳定 |
| Few-shot + GLM（现方案）| 无额外依赖，4个示例即可准确分类 | 多一次 API 调用 |

**实际代码**：`supervisor.py` 第7行注释："意图识别使用 Few-shot Prompt + GLM，无需 semantic-router 依赖"

---

### 10.2 HyDE：为什么用假设文档而不是直接用问题检索？

**问题的本质**：用户问题（短、口语化）与财报片段（长、专业化）之间存在语义 Gap。

```
问题：  "茅台2023年净利润增速如何？"（18字）
文档：  "本报告期内，公司实现归属于母公司股东的净利润为747.34亿元
         较上年同期增长19.16%..."（专业财务表述）
```

HyDE 让 LLM 先生成一段"像真实财报一样的文字"，向量空间上与真实文档更接近，召回率显著提升。

---

### 10.3 ReAct 实现差异

| Agent | ReAct 实现方式 | 说明 |
|-------|--------------|------|
| RetrievalAgent | 简化版（固定最多2轮） | 检索不足时改写问题重试，非标准循环 |
| FinancialAgent | 无 | 单次 LLM 调用 |
| RiskAgent | 无 | 单次 LLM 调用 |
| **RealtimeAgent** | **标准 ReAct** | 使用 `create_react_agent`，由 LangGraph 管理工具调用循环 |

---

### 10.4 MCP 工具注册 vs 直接 @tool 调用

代码中存在两种工具接入方式：

| 方式 | 位置 | 状态 |
|------|------|------|
| MCP Server（`server.py`） | 通过 stdio 传输注册为标准 MCP 工具 | 已实现，可独立启动 |
| 直接 `@tool`（`realtime_agent.py`） | 直接包装函数为 LangChain Tool | **实际运行时使用此方式** |

`realtime_agent.py` 中直接 `from src.mcp.tools import get_stock_quote` 并用 `@tool` 装饰，没有走 MCP 协议层。MCP Server 可作为独立服务供外部系统调用。

### 10.5 防数学幻觉设计

```python
# ❌ 不这样做：让 LLM 计算财务指标
```
